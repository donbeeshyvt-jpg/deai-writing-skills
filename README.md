# deai-writing-skills

將文章用去 AI 味道並且加上自己風格的技能包。四個核心技能：一個從零生成、一個檢查既有文字、一個把某人的口吻蒸餾；外加一個 SEO 擴充，讓同一篇成稿排得上搜尋、發得動社群。

[English](README.en.md) | **繁體中文**

---

## 這是什麼

四個自包含的核心技能，處理中文寫作的三件事：從零生成、檢查既有文字、提煉某人的口吻。另有一個 SEO 擴充 `deai-writing-seo`，把同一套去 AI 味規則接到搜尋與社群場景。每個技能就是一份 `SKILL.md`（純文字），配一個放細節表的 `references/`。

不綁任何平台。每份 `SKILL.md` 裡都有一段可整段貼的操作 prompt，貼進任何吃 system prompt 的 AI 就能用，什麼平台都能裝。用 Claude Code 的話可以把資料夾放進技能目錄自動變成斜線指令，但那只是其中一種用法，不是必要條件。

這份 README 是用 `deai-write` 寫的。如果工具有效，它自己的門面就不該讀起來像機器寫的。

## 三個核心技能

| 技能 | 做什麼 | 什麼時候用 |
|---|---|---|
| `deai-write` | 從主題加素材，直接生成一篇繁中成稿。blog、social、docs、email、landing、script 都能寫。禁用句型在生成當下就不寫，不是先寫完再洗。 | 手上有主題和素材，要寫一篇從初稿就沒有 AI 味的新內容。 |
| `deai-guard` | 檢查既有繁中文本的 AI 味，出證據化報告（風險分數、五維度、逐條命中），然後停下來問你要改哪些，收到確認才動手。 | 文章已經寫好，想檢查，或想檢查完再改。 |
| `deai-voice` | 把某人的說話或寫作方式反向分析，打包成一個可攜的「口吻資料包」：整篇分析資料、一段詳細生成 prompt、內建去 AI 味守則，貼給任何 AI 就能照這個人的口吻寫，或當角色卡交棒。 | 想讓生成的文字帶特定人的口吻，不是通用的自然文風。 |

## SEO 擴充：deai-writing-seo

| 技能 | 做什麼 | 什麼時候用 |
|---|---|---|
| `deai-writing-seo` | `deai-write` 的 SEO 擴充包。輸入主題加素材（新寫）或一篇原稿（改寫），輸出意圖清楚、關鍵字放對位置、讀起來沒有 AI 味、還保住作者原聲的成稿。搜尋意圖、關鍵字擺位、標題、內部連結、E-E-A-T、平台適配一起處理。 | 一篇文章要排得上搜尋、發得動社群，又不想寫成關鍵字塞好塞滿的 AI 稿。 |

核心信念：搜尋引擎的演算法在模仿人類讀者的偏好，所以 SEO 的本體是寫作，不是技術。文章讓人讀不下去，排第一名也沒有轉換。它把執行優先序排成七層，SEO 永遠排在事實正確與作者意圖後面。

## 四條共用底線

四個技能都守同樣這四條。

1. **不做身分判決。** 技能只說「這幾處呈現 N 個 AI 味特徵」。絕不說「這一定是 AI 寫的」，也不給任何生成機率百分比。

2. **誠實邊界。** 不編造事實、數字、第一手經驗。查不到的具體資訊標 `[待補]` 或 `[待查]`，寧可留白也不填假貨。

3. **偵測會誤判，所以降級。** 短文、技術文件、公文、學術摘要、非母語中文、SEO 制式文，一律降強度處理，不硬判 AI 味。

4. **保護片段不動。** 改寫時不碰數字、術語、引用、命令、專有名詞。改寫是換句話說，不是換內容。

## 怎麼用

貼進任何 AI 就能用。打開任一份 `SKILL.md`，把裡面那段操作 prompt 整段複製，貼進 ChatGPT、Claude、Gemini 或你在用的對話式 AI，它就照同一套步驟走。不用安裝、不綁平台。

用 Claude Code 的話更順手。把四個資料夾放進技能目錄（全域 `~/.claude/skills/`，或某個專案的 `.claude/skills/`），重啟後就自動變成 `/deai-guard`、`/deai-voice`、`/deai-write`、`/deai-writing-seo`，講到觸發詞就會自己啟動。

要拿檔案，clone 這個 repo：

```
git clone https://github.com/donbeeshyvt-jpg/deai-writing-skills.git
```

沒有建置步驟，沒有依賴。

## 最小用法

### deai-write

觸發詞是 寫一篇貼文、生成文章、或「直接寫出沒有 AI 味的內容」這類話。動筆前它先問五件事：主題、素材（以及每份素材是你本人的、官方的、還是待查的）、場景、目標讀者、你要讀者讀完做什麼。它先出一份施工圖，你確認後才寫全文，交稿時 11 項加 5 維自檢已經跑過。缺口標成 `[待補]` / `[待查]`，不會拿假數字填。

### deai-guard

你打「檢查 AI 味」「去 AI 味」或「幫我看這篇像不像 AI 寫的」，它就啟動。它先問一句：只出報告，還是檢查完幫你改。接著出報告，附風險分數、五維度分數，每一條命中都列出原句、問題、為什麼像 AI、建議改法、可能誤判。然後停在硬性閘門，問你要改哪幾條。沒收到你的選擇，一個字都不動。改完給你 before / after diff，再做一次殘留檢查。

### deai-voice

說「提煉語氣」「蒸餾說話方式」或「抓某人的寫作習慣」就會跑。它先過授權閘門：只收你本人、你被授權代理、或具名公眾人物的公開內容。一個特徵要跨三份以上樣本重複，才進核心層，每條特徵都標信心等級。你會拿到一個「口吻資料包」：整篇反向分析後的結構化資料、一段詳細的生成 prompt（內建去 AI 味守則與反漫畫化頻率上限）、加一個角色卡視圖，單一區塊貼到任何 AI 就能用。人讀用的完整 profile 保留為審閱來源。

### deai-writing-seo

說「SEO 優化」「改寫成 SEO 文章」「融入關鍵字」「幫我下標題」或「這篇想排上搜尋」就會跑。它先問任務型態（新寫、原稿 SEO 化、社群轉換、局部微調）、主題與核心關鍵字、素材、受眾、平台、目的，缺欄就問。改寫型會先通讀原稿，寫出核心目的與預期效果的推測回報給你確認，推測錯了整組重評，同時鎖定不可改動內容（數據、步驟、立場、慣用語）。搜尋意圖靠直接看第一頁的內容形式判讀，不用猜。動筆前先給你 SEO 藍圖，關鍵字按權重擺位，一頁只鎖一個核心意圖。演算法規則一律當推測性參考，不寫成已驗證事實。

## 怎麼串

四個技能設計成能互相交棒。

```
deai-voice  →  deai-write  →  deai-guard
 抽語氣          填進 §0        獨立複審
                風格輸入
```

用 `deai-voice` 抽出語氣，把它的短 prompt 填進 `deai-write` §0 的「風格輸入」欄，生成，再用 `deai-guard` 獨立複審一次。voice 的短 prompt 也能直接餵給 `deai-guard`，把「改得更自然」對齊成「改得更像某人」。

要 SEO 的時候接 `deai-writing-seo`：它出 SEO 藍圖與規格，填進 `deai-write` §0 的輸入合約生成，成稿再用 `deai-guard` 複審一次，確認 SEO 化沒有帶進 AI 味。要帶特定口吻，就把 `deai-voice` 的資料包一起填進生成端，口吻與 SEO 規格並行不衝突。

分開用都行，串起來只是可選。

## 限制與已知待處理

- 偵測不是證明。風險分數低不代表這篇一定是人寫的，分數高也不代表一定是機器寫的。技能是在替特徵排序，不是在判作者是誰。

- 以繁中為主。規則是針對繁體中文和中英混排調的，其他語言不在範圍內。

- **演算法規則多屬推測。** `deai-writing-seo` 用到的社群與搜尋演算法規則沒有官方完整文件，技能一律標成推測性參考，不寫成已驗證事實。排名會不會動，最終看內容品質。

- **前身技能未收錄於本 repo。** 幾份 `SKILL.md` 裡提到前身姊妹技能（`ai-tone-audit`、`de-ai-rewrite`、`voice-style-distill`）和一份 `NEW_SKILLS_COMPARISON.md`。這些檔案不在這個 repo 裡。如果你在某個 `SKILL.md` 裡看到它們被提到，那是指前身技能，它們在這個 repo 之外。
