# 去 AI 味：檢查、確認、才改寫

## 這個技能在做什麼

這是一個有煞車的去 AI 味工具。它不會拿到文章就直接改，而是走四段：嚴格檢查、出證據化報告、停下來問使用者要改哪些、收到確認後才動手。改完再做一次殘留檢查，回報還剩什麼。

為什麼要有這個煞車。偵測器和規則都會誤判。非母語中文、SEO 文、技術文件、公文、學術摘要本來就比較規則化，硬判會冤枉。使用者手上的文章可能有他自己刻意的安排（某段就是要整齊、某個術語不能動）。所以改動之前一定停下來，把判斷權交回使用者。這是信任邊界，不是禮貌。

三條底線，任何情況都不破：

1. 確認之前絕不改全文。可以標問題、可以出建議，但不落筆。
2. 絕不說「這一定是 AI 寫的」。只說「這幾處呈現 N 個 AI 味特徵」，並附可能誤判的理由。
3. 不動事實、數字、術語、引用、命令、專有名詞。改寫是換句話說，不是換內容。

## 兩種模式，先問清楚

使用者的需求分兩種，開場先判斷是哪一種：

- **只檢查（audit-only）**：使用者要一份報告，自己決定怎麼改。走到「出報告」就停，不進改寫。
- **檢查加改寫（audit-then-fix）**：使用者要你幫忙改，但要先看報告再決定。走完整四段流程。

判斷不出來就直接問一句：「你要我只出一份檢查報告，還是檢查完之後幫你改（改之前會先問你要動哪些）？」

## 嚴格執行流程

流程分四段，每段做完才進下一段。中間有一個硬性閘門，沒收到使用者選擇就不准跨過去。

### 第一段：判型與鎖保護片段（不改任何字）

**步驟 1，判文本類型。** 不同文類的 AI 味門檻不同，先定位：

| 類型 | 判斷信號 | 檢查基調 |
|---|---|---|
| blog／長文 | 有 H 標籤、段落成篇、要傳達觀點 | 完整五維度 |
| social／貼文 | 短、口語、平台語氣 | 輕量，只看最嚴重的命中 |
| docs／技術文件 | 術語密集、步驟、設定說明 | 只清開場結尾，術語全鎖 |
| landing／文案 | 賣點、CTA、轉化導向 | 保留 SEO 結構，只改段落節奏 |
| academic／學術摘要 | 背景鋪陳、被動語態、引用格式 | 大幅降級，鋪陳是文類需求 |
| email／公文 | 稱謂、制式結尾、法規語 | 幾乎不判，只清明顯機械開場 |
| other | 判不出來 | 問使用者這是什麼場景 |

**步驟 2，量文本長度並決定降級。**

- 500 字以上：完整流程。
- 300 到 500 字：只出「風險等級 + 最嚴重的 3 條命中 + 修正方向」，不做五維度評分。
- 300 字以下：只看「邏輯有無矛盾」和「用詞有無明顯拼接痕跡」，其餘不判，直接說明「短文本信號不足，只做輕量判斷」。

**步驟 3，鎖保護片段。** 這些一律不動，先標記起來，改寫時繞開：

- 直接引用、引號內的話。
- 程式碼、命令、設定值、檔名、路徑。
- 數字、百分比、日期、金額、版本號、型號。
- 專有名詞、品牌、人名、機構名、術語。
- 報錯訊息、系統主語。
- 使用者明講「這段不要動」的部分。

**步驟 4，查語言版本一致性。** 繁簡混用、翻譯腔痕跡要標記，但先問「這是你自己寫的還是翻譯或改寫過的」。非母語或翻譯來源，詞彙層與翻譯腔的權重要調低，重點放內容密度和邏輯，不要拿「透過…來實現」直接判 AI。

### 第二段：逐段檢查並算分（仍不改字）

按下面的偵測訊號逐段掃，命中就記下證據。訊號有優先順序，內容空泛權重最高，節奏過勻權重最低。單一命中不算數，要看聚集：同一段命中多個訊號才算真問題。

**偵測訊號優先序（高到低）：**

1. 內容是否空泛（只宣告重要性、不給具體）。
2. 來源是否模糊（權威聲稱無具名來源）。
3. 結構是否模板化（開場套話、二元對比、升華收尾）。
4. 語氣是否漂移（前面口語後面公關腔）。
5. 節奏是否過度平均（句長、段長、轉折詞頻率幾乎沒有變化）。
6. 是否缺個人觀察、取捨、限制。

命中詞彙但內容具體、有來源、有判斷的，一律降級，不扣分。

**五維度評分（各 0 到 100，越高越像 AI，短文本略過此表）：**

| 維度 | 問的問題 | 高分特徵 |
|---|---|---|
| 空泛度 | 有沒有講具體的事 | 抽象名詞堆疊、宣告重要性不給例子 |
| 來源感 | 主張有沒有出處 | 「研究顯示、專家指出」無具名 |
| 模板度 | 結構是不是公式 | 宏大開場、不僅…更…、金句收尾 |
| 節奏勻稱度 | 句長段長是不是機械 | 連續等長、每段都有粗體 |
| 聲音缺失度 | 有沒有真人立場 | 全篇無第一人稱、無限制、無取捨 |

**總分 = 五維度加權平均**（空泛度、來源感權重高，節奏勻稱度權重低）。分數只是排序工具，不是判決。報告附一句：「分數用於排序命中的嚴重度，不代表 AI 生成機率。」評分錨點與各文類降級係數在 `references/scoring-rubric.md`。

**高風險 AI 味的必要判定（滿足越多越確定，屬質性判斷，不用湊百分比）：**

- 開場整段都是預告，沒有內容。
- 段落結構完全規則，句長、空行、轉折詞頻率幾乎沒有變化。
- 抽象名詞明顯多於具體施事者（展現、體現、賦能、打造，找不到誰做的）。
- 權威聲稱無來源，同時缺數字與例子。
- 全文缺個人立場、限制、取捨、真實觀察。

滿足 1 到 2 項是中度風險，3 項以上是高風險。

### 第三段：出證據化報告

報告是給使用者做決定用的，所以每一條都要能被復核。用這個固定格式（可貼模板全集在 `references/report-templates.md`）：

```
## AI 味檢查報告

文本類型：<blog／social／docs…>　字數：<N>　降級狀態：<無／中度／短文本輕量>
AI 味風險分數：<0-100>　風險等級：<低／中／高>

五維度：
　空泛度 <分> ｜ 來源感 <分> ｜ 模板度 <分> ｜ 節奏勻稱度 <分> ｜ 聲音缺失度 <分>

逐條命中（依嚴重度排序）：

【high】
　原句：「<命中的句子>」
　問題：<哪一類 AI 味>
　為什麼像 AI：<命中的具體模式，例：宏大開場加抽象名詞堆疊>
　建議改法：<具體怎麼改，給方向不代改>
　可能誤判：<這條在什麼情況下其實正常，例：SEO 標題本來就重複關鍵字>

【medium】
　…（同上格式）

【low】
　…（同上格式）

已鎖定不動：
　<列出保護片段：數字／術語／引用／命令，說明為什麼不碰>

需要你補資料：
　<標 [待查]／[待補] 的地方，例：「研究顯示」缺具名來源>
```

每條命中都要有「可能誤判」欄，這是這個技能和單純偵測器的差別。來源相關的評論一律標明：`[待查]` 是查不到但理應有；`[無來源]` 是明顯自產（例如「根據我們的研究」但作者不是研究機構）；`[來源已揭露]` 是模糊權威但揭露了，風險降級。

### 硬性確認閘門（不可跳過）

報告出完，**停下來**。只有 audit-then-fix 模式才進到這裡；audit-only 到報告就結束。

貼這段給使用者，一字不改地問：

```
以上是檢查結果。改動之前我需要你決定要動哪些。請選一個：

　(1) 全部改　　　按標準模式改所有命中（high／medium／low 都改）
　(2) 只改 high　只處理嚴重度 high 的，其餘保留
　(3) 逐條勾選　你告訴我要改第幾條（例：改 1、3、5）
　(4) 都不改　　只保留這份報告供你參考，我不動任何字
　(5) 自訂　　　你直接說怎麼改（例：只清開場、保留所有粗體）

還有幾個保護預設，你也可以覆蓋：
　- 數字、術語、引用、命令我一律不動，除非你說要動
　- 標 [待查]／[待補] 的地方我不會自己補，會留給你

你選哪個？
```

閘門規則：

- 沒收到明確選擇，不准改任何字。使用者沒回或回得模糊，再問一次，不要自作主張。
- 選 (4) 就到此為止，不改。
- 改寫過程中若發現新問題，不要中途再問，先改完，留到殘留再檢查時一次說。
- 這個閘門只出現一次，就在改寫之前。不要改一半又跳出來問。

### 第四段：執行改寫並出 diff

收到選擇後才動手。策略預設保守，只有使用者明說要大改才升級。動作對照庫在 `references/rewrite-moves.md`。

**策略選擇：**

| 文本類型 | 預設策略 | 說明 |
|---|---|---|
| blog／social／文案 | standard + bounded | 改句子、段落、節奏；整句空話列出來建議刪，重要的刪改要標示 |
| docs／技術文件／公文／學術 | minimal + in-place | 只清明顯 AI 開場和結尾，術語不碰，結構不動 |
| 使用者明說要大改 | aggressive + structural | 才升級到重組結構 |

**改寫動作表**（照命中類型選動作）：

| 命中類型 | 改寫動作 |
|---|---|
| 宏大開場（在當今…時代） | 刪掉暖場，第一句直接破題直答 |
| 二元對比（不是 A 而是 B／不僅…更…） | 刪前半否定，直接說 B |
| 空泛重要性（至關重要、不可或缺） | 換成不做的具體後果，或刪 |
| 模糊權威（研究顯示、專家指出） | 改具名來源年份，查不到標 [待查]，或改「我的觀察」 |
| 翻譯腔（透過…來實現） | 拆成主語加動詞的直述句 |
| 抽象形容詞（很擠、超香、好累） | 換物理參數、品牌型號、數值、動作 |
| 抽象名詞當動詞（賦能、打造、彰顯） | 換具體動詞，或改「是／有」 |
| 升華收尾（這讓我想起、其實這就是人生） | 換冷點收尾，停在物理事實或未解決問題 |
| 假代理（決策浮現、數據告訴我們） | 補回真正的施事者（誰做的） |
| 同義詞輪轉（開發者→工程師→建構者） | 改回重複同一個關鍵詞 |
| 三項排比、破折號「——」濫用 | 改兩項或一項；破折號換逗號、句號、括號 |
| 半形標點混入中文 | 全部轉全形 `，。：；！？（）「」` |

**保真回讀（改完必做，防編造）：**

改完逐句對照原文，確認沒犯這些：

- 有沒有新增原文沒有的事實、數字、引用。有就是編造，退回標 [待查] 或 [待補]。
- 有沒有把「誰做」的施事者改丟了（國家推動改成推動，丟了國家）。
- 有沒有把推測寫成了結論。
- 有沒有動到保護片段。
- 標點有沒有被自動轉錯（尤其全半形、破折號）。

**出 diff（三區呈現，不要貼整篇 markdown diff）：**

```
## 改動說明

改了什麼：
　- 「<改前片段，含前後 5 到 10 字>」→「<改後>」
　　原因：<刪開場冗句／模糊權威改具名／…>
　-（逐條列，每條都帶原因）

保留未動：
　- <列強點或容易誤判的段落，說明為什麼沒改>

仍需你補：
　- <標 [待補] 的地方，例：某數字找不到來源>
```

每條 diff 都要帶「為什麼改」，不然使用者無法復核。

### 殘留再檢查（residual re-audit）

改完自動過一輪輕量檢查，只看五項：開場、結尾、旁白、空泛判斷、句長過勻。發現殘留就回報：

```
殘留檢查：
　- 第 X 段可能還有 <什麼>，要不要再處理？
　　(1) 我再改一次　(2) 你自己調　(3) 忽略，就這樣
```

殘留檢查最多兩輪，避免「改、檢查、再改」無限迴圈。使用者選忽略或核准後，這版就是最終版，不再自動檢查。

## 可直接貼的操作 prompt

如果要把這個技能當一段獨立 prompt 給另一個 AI 或人執行，貼這段：

```
你要對我貼的中文文章做「去 AI 味檢查」，嚴格照以下步驟，不要跳步。

先問我一句：要「只出檢查報告」，還是「檢查完幫我改（改之前先問我改哪些）」。我回答後才開始。

第一段：先判文本類型（blog／貼文／技術文件／文案／學術／公文），量字數。
　500 字以下降級處理。鎖定保護片段：數字、術語、引用、命令、專有名詞，這些不准動。
第二段：逐段檢查 AI 味，按「內容空泛 > 來源模糊 > 結構模板 > 語氣漂移 > 節奏過勻」的優先序。
　單一命中不算，要同段聚集才算。算出 0 到 100 風險分數和五維度分數。
第三段：出報告，每條命中要有：原句、問題、為什麼像 AI、建議改法、可能誤判。
　不准說「這一定是 AI」，只說「呈現 N 個特徵」。

【停下來】如果我選的是「幫我改」，問我要改哪些，給我五個選項：全部改／只改 high／逐條勾選／都不改／自訂。
　沒等到我回答，不准改任何字。（如果我一開始選「只出報告」，到這裡就結束。）

第四段：我確認後才改。改完做保真回讀（沒新增事實、沒改丟施事者、沒動術語），
　出 diff（改前→改後加原因），再做一次殘留檢查回報。

寫作規範：繁體中文、全形標點、禁破折號「——」。不編造事實數字，查不到標 [待查]。
```

## 輸出格式總表

- 檢查報告：見第三段固定格式。
- 確認閘門：見閘門固定問句，五選項一字不改。
- 改動 diff：見第四段三區格式。
- 殘留回報：見殘留再檢查格式。

## 禁止事項

- 確認閘門前改任何一個字。
- 說「這一定是 AI 寫的」「AI 生成機率 X%」。只能說呈現幾個特徵。
- 改寫時新增原文沒有的事實、數字、引用、第一手經驗。
- 動保護片段（數字、術語、引用、命令、專有名詞）。
- 把模糊權威自動補成看似具體的假來源（「研究顯示」補成「根據 OpenAI 官方」）。
- 短文本、技術文件、公文、學術摘要、非母語中文、SEO 文硬判 AI 味。
- 為了口語化刪掉 SEO 的 title、H 標籤、編號步驟、FAQ 結構。
- 技能本身的文字帶 AI 味：不用「不僅…更…」「值得注意的是」「總而言之」「讓我們深入探討」「在當今…的時代」。
- 中途反覆詢問。閘門只問一次，殘留最多兩輪。
- 用未經來源的具體百分比替換原文（本技能自身也守誠實邊界，不自產假數字）。

## 與其他技能搭配

- **要從零寫**：要從主題和素材直接寫出沒有 AI 味的新文章，用 `deai-write`，不是這個。這個技能處理已經寫好的文本。
- **要套某人口吻**：如果使用者要的是「改成某人的說話方式」而不只是「去掉 AI 味」，先用 `deai-voice` 產出 voice profile。若改寫時附上 profile，本技能的改寫目標就從「改得更通用自然」切換成「改得更貼近該 profile」，其餘流程與閘門不變。
- 三個技能共用同一套誠實邊界：不編造事實數字第一手經驗，查不到標 [待補]／[待查]；偵測器會誤判，不當唯一判決；短文、技術文、公文、學術摘要、非母語、SEO 文降級。
- 專案另有既有前身技能 `ai-tone-audit`（只檢查）與 `de-ai-rewrite`（只改寫）。本技能把兩者合一並加確認閘門；差異見資料夾內 `NEW_SKILLS_COMPARISON.md`。
