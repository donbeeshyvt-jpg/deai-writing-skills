# 報告與模板全集

這裡收 `deai-guard` 流程會用到的所有可貼模板，方便複製。每個模板下面附一個填好的中文實例，示範填出來長怎樣。實例裡的分數、命中內容都是示範用，實際套用時要換成當次真實檢查的結果。

模板一覽：

| 編號 | 模板 | 用在哪一段 |
|---|---|---|
| 一 | 完整檢查報告 | 第三段，500 字以上完整流程 |
| 二 | 短文本輕量報告 | 第三段，300 到 500 字或降級文本 |
| 三 | 確認閘門五選項問句 | 硬性閘門，audit-then-fix 才用 |
| 四 | 改動 diff 三區 | 第四段，改寫完呈現 |
| 五 | 殘留再檢查回報 | 殘留再檢查段 |
| 六 | audit-only 結束語 | 只檢查模式，到報告就停 |

三個提醒，套模板前先看：

- 標點一律全形「，。：；！？（）「」」，英文與數字前後留半形空格。
- 每條命中都要有「可能誤判」欄，這是這個技能和單純偵測器的差別，不能省。
- 分數只是排序命中嚴重度用的，報告裡要保留那句「分數用於排序命中的嚴重度，不代表 AI 生成機率」，不要拿掉。

## 一、完整檢查報告模板

500 字以上、走完整流程時用這個。含五維度、逐條命中（high／medium／low 分級）、已鎖定不動、需要你補資料四區。

### 空白模板

```
## AI 味檢查報告

文本類型：<blog／social／docs／landing／academic／email／other>　字數：<N>　降級狀態：<無／中度／短文本輕量>
AI 味風險分數：<0-100>　風險等級：<低／中／高>

分數用於排序命中的嚴重度，不代表 AI 生成機率。

五維度：
　空泛度 <分> ｜ 來源感 <分> ｜ 模板度 <分> ｜ 節奏勻稱度 <分> ｜ 聲音缺失度 <分>

逐條命中（依嚴重度排序）：

【high】
　原句：「<命中的句子，含前後文足以定位>」
　問題：<哪一類 AI 味，例：宏大開場>
　為什麼像 AI：<命中的具體模式，例：整段都是預告，沒有講到內容>
　建議改法：<具體怎麼改，給方向不代改>
　可能誤判：<這條在什麼情況下其實正常>

【medium】
　原句：「<……>」
　問題：<……>
　為什麼像 AI：<……>
　建議改法：<……>
　可能誤判：<……>

【low】
　原句：「<……>」
　問題：<……>
　為什麼像 AI：<……>
　建議改法：<……>
　可能誤判：<……>

已鎖定不動：
　- <保護片段，說明為什麼不碰，例：「4090」是型號，鎖定>
　- <……>

需要你補資料：
　- <標 [待查]／[待補]／[無來源] 的地方，例：「研究顯示」缺具名來源，標 [待查]>
　- <……>
```

來源相關的評論用這三個標記分清楚：`[待查]` 是查不到但理應有出處；`[無來源]` 是明顯自產（例如寫「根據我們的研究」但作者不是研究機構）；`[來源已揭露]` 是模糊權威但作者揭露了身分，風險降級。

### 填好的實例

```
## AI 味檢查報告

文本類型：blog　字數：640　降級狀態：無
AI 味風險分數：71　風險等級：高

分數用於排序命中的嚴重度，不代表 AI 生成機率。

五維度：
　空泛度 78 ｜ 來源感 74 ｜ 模板度 80 ｜ 節奏勻稱度 55 ｜ 聲音缺失度 68

逐條命中（依嚴重度排序）：

【high】
　原句：「在這個資訊爆炸的時代，選對筆電已經成為每個創作者不可忽視的重要課題。」
　問題：宏大開場加空泛重要性
　為什麼像 AI：開頭整句都在鋪陳「這件事很重要」，沒有講到任何一台筆電或一個具體需求，是典型的暖場套話。
　建議改法：刪掉這句，第一句直接破題，例如寫你當初挑筆電卡在哪個規格。
　可能誤判：如果這是 SEO 導言且下一段馬上進入具體規格，鋪陳可稍微保留，但這篇下一段仍是空話，不豁免。

【medium】
　原句：「這款筆電不僅效能強悍，更能為你的創作賦能。」
　問題：二元遞進句式加抽象名詞當動詞
　為什麼像 AI：「不僅…更…」是模板遞進，「賦能」是抽象名詞硬當動詞，讀完不知道它具體能做什麼。
　建議改法：拆成兩句直述，講清楚「效能強」是指哪個場景不卡，例如「跑 4K 影片剪輯時預覽不掉幀」。
　可能誤判：若原文後面立刻接了實測數據，這句只是過場，可降為 low，但本文沒有接數據。

【low】
　原句：「總而言之，這是一台值得入手的好筆電。」
　問題：升華收尾加空泛結論
　為什麼像 AI：用「總而言之」硬做總結，結論停在「值得入手」這種沒有資訊量的話。
　建議改法：換成冷點收尾，停在一個具體事實或還沒解決的顧慮，例如續航實測只有五小時這件事。
　可能誤判：如果通篇是導購結論頁，收尾喊一句結論屬版型需求，可放寬，但本文是評測長文，不豁免。

已鎖定不動：
　- 「RTX 4090」「32GB」是型號與規格，鎖定，不改。
　- 「售價 62,900 元」是金額，鎖定。
　- 引號內那句廠商標語「為創作而生」是直接引用，鎖定。

需要你補資料：
　- 第三段「根據多數專業評測」缺具名來源，標 [待查]，你補上是哪一家評測或改成你自己的實測。
　- 第五段「電池可用一整天」沒有時數，標 [待補]，你補實測小時數。
```

## 二、短文本輕量報告模板

300 到 500 字，或文類降級（social、docs 只清開場結尾）時用。不做五維度評分，只給風險等級、最嚴重的三條命中、修正方向。300 字以下再降一級，只看邏輯有無矛盾和用詞有無拼接痕跡。

### 空白模板

```
## AI 味檢查報告（輕量）

文本類型：<social／docs／短 blog…>　字數：<N>
說明：短文本信號不足，只做輕量判斷，不做五維度評分。
風險等級：<低／中／高>

最嚴重的命中（最多三條）：

1. 原句：「<……>」
　 問題：<……>
　 建議方向：<……>
　 可能誤判：<……>

2. …（同上）

3. …（同上）

已鎖定不動：
　- <保護片段>

需要你補資料：
　- <標 [待查]／[待補] 的地方，沒有就寫「無」>
```

### 填好的實例

```
## AI 味檢查報告（輕量）

文本類型：social　字數：180
說明：短文本信號不足，只做輕量判斷，不做五維度評分。
風險等級：中

最嚴重的命中（最多三條）：

1. 原句：「在快節奏的生活中，一杯好咖啡至關重要。」
　 問題：宏大開場加空泛重要性
　 建議方向：貼文開頭直接講這杯咖啡是哪一款、喝起來怎樣，把暖場那半句刪掉。
　 可能誤判：貼文若走情境行銷，第一句氣氛鋪陳是常見寫法，但這句沒有接任何具體，仍偏 AI 腔。

2. 原句：「這款豆子不僅香氣濃郁，更帶來層次豐富的口感。」
　 問題：二元遞進句式加抽象形容詞
　 建議方向：把「香氣濃郁」「層次豐富」換成喝得到的具體，例如聞起來像什麼、尾韻是酸還是苦。
　 可能誤判：貼文字數本來就少，形容詞密一點正常，但兩個抽象形容詞連用仍建議至少換一個成具體。

已鎖定不動：
　- 「衣索比亞耶加雪菲」是產地品名，鎖定。
　- 「售價 380 元」是金額，鎖定。

需要你補資料：
　- 無。
```

## 三、確認閘門五選項問句

audit-then-fix 模式，報告出完停下來，貼這段給使用者，一字不改。audit-only 模式不進這裡。這段和 SKILL 的閘門一致，直接複製，不要改字。

```
以上是檢查結果。改動之前我需要你決定要動哪些。請選一個：

　(1) 全部改　　　按標準模式改所有命中（high／medium／low 都改）
　(2) 只改 high　只處理嚴重度 high 的，其餘保留
　(3) 逐條勾選　你告訴我要改第幾條（例：改 1、3、5）
　(4) 都不改　　只保留這份報告供你參考，我不動任何字
　(5) 自訂　　　你直接說怎麼改（例：只清開場、保留所有粗體）

還有幾個保護預設，你也可以覆蓋：
　- 數字、術語、引用、命令我一律不動，除非你說要動
　- 標 [待查]／[待補] 的地方我不會自己補，會留給你

你選哪個？
```

閘門規則提醒（給執行者看，不貼給使用者）：沒收到明確選擇不准改字，回得模糊就再問一次；選 (4) 到此為止；這個閘門只出現一次，就在改寫之前，不要改一半又跳出來問。

## 四、改動 diff 三區模板

第四段改寫完用這個呈現，三區：改了什麼、保留未動、仍需你補。每條 diff 都要帶「為什麼改」，不然使用者無法復核。不要貼整篇 markdown diff，用這個三區格式。

### 空白模板

```
## 改動說明

改了什麼：
　- 「<改前片段，含前後 5 到 10 字>」→「<改後>」
　　原因：<刪開場冗句／模糊權威改具名／抽象換具體…>
　- 「<……>」→「<……>」
　　原因：<……>

保留未動：
　- <列強點或容易誤判的段落，說明為什麼沒改>
　- <……>

仍需你補：
　- <標 [待補]／[待查] 的地方，例：某數字找不到來源，需要你提供>
　- <……>
```

### 填好的實例

```
## 改動說明

改了什麼：
　- 「在這個資訊爆炸的時代，選對筆電已經成為每個創作者不可忽視的重要課題。」→「我上次換筆電卡在顯卡選型，剪 4K 影片到底要不要上 4090。」
　　原因：刪宏大開場，第一句直接破題，換成具體的挑選卡點。
　- 「這款筆電不僅效能強悍，更能為你的創作賦能。」→「跑 4K 剪輯時預覽不掉幀，多軌套色也還算穩。」
　　原因：拆掉「不僅…更…」遞進句式，「賦能」換成具體場景表現。
　- 「總而言之，這是一台值得入手的好筆電。」→「唯一讓我猶豫的是續航，實測滿載只有五小時。」
　　原因：刪升華收尾，改停在一個沒解決的具體顧慮。

保留未動：
　- 第四段規格對照表沒動。表格是這篇的資訊密度來源，屬強點，不是 AI 味。
　- 「RTX 4090」「32GB」「售價 62,900 元」全部保留，這些是型號、規格與金額，鎖定片段。

仍需你補：
　- 第三段原本的「根據多數專業評測」我沒有替你補來源，標 [待查]，你決定補是哪一家還是改成自己的實測。
　- 續航那句我寫了「實測五小時」，但這個數字是照你原文推的，若你沒實測過，標 [待補]，先別當定論。
```

保真回讀提醒（改完必做）：逐句對照原文，確認沒新增原文沒有的事實數字引用、沒把施事者改丟、沒把推測寫成結論、沒動到保護片段、標點沒轉錯。上面實例最後一條就是這個原則的體現，數字來源不確定就標 [待補]，不硬當定論。

## 五、殘留再檢查回報模板

改完自動過一輪輕量檢查，只看五項：開場、結尾、旁白、空泛判斷、句長過勻。發現殘留就用這個回報。最多兩輪，避免無限迴圈。

### 空白模板

```
殘留檢查：
　- 第 <X> 段可能還有 <什麼殘留，例：結尾仍偏升華>，要不要再處理？
　　(1) 我再改一次　(2) 你自己調　(3) 忽略，就這樣
```

一段有多處殘留就逐條列，每條都給同樣三個選項。沒有殘留就直接說「殘留檢查過一輪，沒有發現需要再處理的地方，這版就是最終版」。

### 填好的實例

```
殘留檢查：
　- 第二段開頭「說到創作筆電」這句還帶一點過場暖場的味道，要不要一起清掉？
　　(1) 我再改一次　(2) 你自己調　(3) 忽略，就這樣
　- 第五段結尾「希望這篇對你有幫助」偏公關收尾，要不要換成更冷的收法或直接刪？
　　(1) 我再改一次　(2) 你自己調　(3) 忽略，就這樣
```

使用者選忽略或核准後，這版就是最終版，不再自動檢查。

## 六、audit-only 模式結束語

只檢查模式，走到報告就停，不進閘門，不改字。報告出完後貼這段收尾。

### 空白模板

```
以上是檢查報告，供你參考。

你當初選的是「只出報告」，所以我到這裡就停，不動任何字。報告裡標 [待查]／[待補] 的地方我也沒有替你補，留給你決定。

如果之後你想讓我照這份報告幫你改，再跟我說一聲，我會先問你要動哪幾條再動手。
```

### 填好的實例

填好的樣子和空白模板一致，這段是固定收尾語，不含變數，直接貼即可。若使用者在只檢查過程中另外交代過保護片段或特殊要求，可在第二句後補一句回應，例如：

```
以上是檢查報告，供你參考。

你當初選的是「只出報告」，所以我到這裡就停，不動任何字。你先前說第四段表格不要動，我也只在報告裡標了命中，沒有對它提改法。報告裡標 [待查]／[待補] 的地方我也沒有替你補，留給你決定。

如果之後你想讓我照這份報告幫你改，再跟我說一聲，我會先問你要動哪幾條再動手。
```
