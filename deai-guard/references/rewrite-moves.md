# 改寫動作對照庫

這是 deai-guard 第四段（執行改寫）的完整動作庫，比 SKILL 主檔的改寫動作表更細。SKILL 給的是速查表，這裡給每個命中類型的五欄對照、三檔策略的實際差異、保真回讀的逐項清單、無源引用的三種處理、以及冷點收尾與改壞反例。

使用方式：改寫某一條命中前，先在第一節找到對應命中類型，讀完五欄（原句、為什麼像 AI、保護片段、推薦改法、改後範例）再動手。策略選擇看第二節。改完照第三節逐項回讀。遇到無源引用看第四節。

## 目錄

- 一、命中類型五欄對照

## 一、命中類型五欄對照

每個類型五欄：原句樣本、為什麼像 AI、不該改壞什麼（保護片段）、推薦改法、改後中文範例。保護片段那一欄是提醒：改這一條的時候，這些東西不能順手改掉。

### 1. 宏大開場

| 欄位 | 內容 |
|---|---|
| 原句 | 「在當今快速變化的時代，內容創作正面臨前所未有的挑戰。」 |
| 為什麼像 AI | 第一句不進主題，先鋪一層抽象背景。「當今／時代／前所未有」是暖場套語，刪掉不損失任何資訊。 |
| 保護片段 | 如果暖場句裡夾了具體數字或事件（例某年某平台改版），那個具體物要留，只刪抽象殼。 |
| 推薦改法 | 刪掉整句暖場，第一句直接破題，講你實際要說的那件事。 |
| 改後範例 | 「YouTube 這次改推薦演算法，短影音的曝光被砍掉一半，我先講怎麼應對。」 |

### 2. 二元對比（不是 A 而是 B ／ 不僅…更…）

| 欄位 | 內容 |
|---|---|
| 原句 | 「這不只是一個工具，更是一種思維方式的轉變。」 |
| 為什麼像 AI | 用否定前半來墊高後半，是升格套路。前半「不只是一個工具」沒有資訊，只是修辭跳板。 |
| 保護片段 | 如果 A 和 B 是真的兩個不同的東西（例「這不是 bug 是設計」），那是有內容的對比，不要當套路刪。只刪空心的墊高。 |
| 推薦改法 | 刪掉否定前半，直接講 B 是什麼，並補上為什麼。 |
| 改後範例 | 「用這個工具之後，我排版的順序整個倒過來，先想版位再填字。」 |

### 3. 空泛重要性

| 欄位 | 內容 |
|---|---|
| 原句 | 「良好的睡眠對健康至關重要，不可或缺。」 |
| 為什麼像 AI | 只宣告某事重要，不給具體。「至關重要／不可或缺／扮演關鍵角色」是佔位詞，讀者知道重要，想知道的是怎樣、多少、不做會怎樣。 |
| 保護片段 | 別把主題名詞（睡眠、健康）改掉。要換的是「至關重要」這個空殼，不是句子在講的事。 |
| 推薦改法 | 換成不做會有的具體後果，或直接刪掉這句補一個實例。 |
| 改後範例 | 「連續幾天睡不到五小時，我隔天剪片會漏掉明顯的跳點，重剪一次等於多花一小時。」 |

### 4. 模糊權威

| 欄位 | 內容 |
|---|---|
| 原句 | 「研究顯示，人的專注力只能維持八秒。」 |
| 為什麼像 AI | 訴諸權威但沒有具名來源。哪個研究、誰做的、哪一年，都沒有，讀者無法查證。 |
| 保護片段 | 那個數字（八秒）本身是保護片段，不准自己改成別的數字。改的是「研究顯示」這個模糊出處，不是數字。 |
| 推薦改法 | 三選一：查得到就補具名來源與年份；查不到就標 [待查]（處理方式見第四節）；本來就是自己觀察就改成「我的觀察」。絕不自己編一個看似具體的來源。 |
| 改後範例（改觀察） | 「我自己拍片的經驗，觀眾大概前幾秒沒被勾住就會滑掉，這是我看後台留存曲線的感覺，不是實測數據。」 |

### 5. 翻譯腔

| 欄位 | 內容 |
|---|---|
| 原句 | 「透過使用這個方法，可以實現效率的提升。」 |
| 為什麼像 AI | 「透過…來實現／進行…的動作／對…進行」是英文語法直翻。中文習慣主語加動詞直述，不繞這一圈。 |
| 保護片段 | 非母語作者或翻譯稿本來就會這樣寫，先確認來源（見 SKILL 第一段步驟 4）。若是翻譯稿，這一條權重要調低，不要當成 AI 味硬判。 |
| 推薦改法 | 拆成「誰做什麼」的直述句，把名詞化的動作還原成動詞。 |
| 改後範例 | 「用這個方法，剪片變快了。」 |

### 6. 抽象形容詞（該給參數卻只給感受）

| 欄位 | 內容 |
|---|---|
| 原句 | 「這支麥克風收音效果超好，音質很棒。」 |
| 為什麼像 AI | 「超好／很棒／很擠／好厲害」是空的評價詞，換誰講都一樣，沒有可驗證的具體。這裡吸收 Jemmy Ko 講的內容物理學方向：把感受換成能被量或被指認的物理量。 |
| 保護片段 | 產品名、型號、規格數字（若原文有）不准改。抽象詞要落地，但落地用的具體如果原文沒有，不能自己編出一個規格（例不能自己填「48kHz」），要嘛用原文有的，要嘛改成可觀察的動作。 |
| 推薦改法 | 換成物理參數、品牌型號、可觀察的動作或情境。原文沒給規格就用「做了什麼、聽起來怎樣」的動作描述，不要憑空補數字。 |
| 改後範例 | 「這支麥克風離嘴巴一個拳頭遠講話，冷氣的低頻嗡嗡聲收不太進去，我不用再另外降噪。」 |

### 7. 抽象名詞當動詞（賦能、打造、彰顯）

| 欄位 | 內容 |
|---|---|
| 原句 | 「這個功能賦能創作者，打造沉浸式體驗。」 |
| 為什麼像 AI | 「賦能／打造／彰顯／構建／助力」是抽象動詞，聽起來有動作其實沒說做了什麼。 |
| 保護片段 | 主體（功能、創作者）留著，換的是動詞。別把句子改到連在講什麼都沒了。 |
| 推薦改法 | 換成具體動詞（給、做、讓、加），或直接用「是／有」把它講成事實。 |
| 改後範例 | 「這個功能讓你把背景音樂的音量單獨拉一軌，觀眾聽人聲不會被蓋掉。」 |

### 8. 升華收尾

| 欄位 | 內容 |
|---|---|
| 原句 | 「說到底，剪輯的不是影片，而是我們對時間的理解。」 |
| 為什麼像 AI | 結尾硬要拔高到人生哲理，「說到底／其實這就是／這讓我想起」是升華套語。把具體的事糊成一句金句，資訊量歸零。 |
| 保護片段 | 如果收尾句裡有一個真的觀察或未解決的問題，留下來，只砍掉升華的那層糖。 |
| 推薦改法 | 換冷點收尾：停在一個物理事實、一個具體動作、或一個還沒解決的問題。不要總結，不要拔高。 |
| 改後範例 | 「這條時間軸我還沒調好轉場，下一支再試看看不加轉場會不會更順。」 |

### 9. 假代理（施事者被抽象名詞頂替）

| 欄位 | 內容 |
|---|---|
| 原句 | 「數據告訴我們，決策的方向已經浮現。」 |
| 為什麼像 AI | 讓抽象名詞（數據、決策）當主語去做事，把真正在做事的人藏起來。數據不會告訴任何人，是人看了數據做判斷。 |
| 保護片段 | 別把原文有的具體數字或事實改丟。補回施事者是加人，不是刪事。 |
| 推薦改法 | 補回真正的施事者，講清楚是誰看了什麼、做了什麼判斷。 |
| 改後範例 | 「我看後台的完播率，決定下一支把開頭砍短。」 |

### 10. 同義詞輪轉

| 欄位 | 內容 |
|---|---|
| 原句 | 「開發者要理解需求，工程師要落實設計，建構者要交付成果。」 |
| 為什麼像 AI | 同一個對象換三個詞來講，怕重複而輪轉，反而讓讀者以為在講三種人。中文不忌諱重複同一個關鍵詞。 |
| 保護片段 | 如果這三個詞真的指三種不同角色，那是有意義的區分，不要合併。只有在指同一群人時才改回同一個詞。 |
| 推薦改法 | 認定是同一對象就改回重複同一個關鍵詞，不要為了不重複而換詞。 |
| 改後範例 | 「工程師要理解需求，把設計落實，交付成果。」 |

### 11. 三項排比堆疊

| 欄位 | 內容 |
|---|---|
| 原句 | 「它高效、它優雅、它強大。」 |
| 為什麼像 AI | 三個等長的短句排比，節奏過勻，且三個形容詞都空。三連排比是 AI 最愛的節奏之一。 |
| 保護片段 | 若三項各自有具體內容（不是空形容詞），那是有效的並列，保留。只有空排比才拆。 |
| 推薦改法 | 砍到一項或兩項，並把空形容詞落地成具體。 |
| 改後範例 | 「它匯出一支十分鐘的 1080p 影片大概三分鐘，我等的時間短到可以不用切出去做別的事。」 |

### 12. 破折號「——」濫用

| 欄位 | 內容 |
|---|---|
| 原句 | 「這個功能很好用——尤其是批次處理——幾乎每天都在用。」 |
| 為什麼像 AI | 破折號當萬用停頓，一句塞兩個。中文本來有逗號、句號、括號可用，破折號濫用是機械節奏的信號。本技能規範也禁破折號。 |
| 保護片段 | 破折號原本框住的補充內容要留，只換掉符號。 |
| 推薦改法 | 要停頓換逗號，要補充換括號或另起一句。全篇不留「——」。 |
| 改後範例 | 「這個功能很好用，尤其是批次處理，我幾乎每天都在用。」 |

### 13. 半形標點混入中文

| 欄位 | 內容 |
|---|---|
| 原句 | 「今天測了三個工具,結果都不太行.其中一個還當機了!」 |
| 為什麼像 AI | 中文句子裡混半形逗號句號驚嘆號，是複製貼上或機器生成留下的痕跡。 |
| 保護片段 | 英文、數字、程式碼、網址裡的半形標點不動。只轉中文語句內的標點。英數與中文之間留半形空格。 |
| 推薦改法 | 中文語句內的標點全轉全形 `，。：；！？（）「」`。 |
| 改後範例 | 「今天測了三個工具，結果都不太行。其中一個還當機了！」 |

## 二、標準／保守／激進三檔策略

三檔策略對應改動幅度。預設保守，使用者明說要大改才升級。選錯檔的代價：保守檔改太少（AI 味殘留），激進檔改太多（改壞內容、動到不該動的）。

### 各檔差異

| 項目 | 保守（minimal + in-place） | 標準（standard + bounded） | 激進（aggressive + structural） |
|---|---|---|---|
| 改動範圍 | 只清開場、結尾、明顯機械開場 | 改句子、段落內部、節奏 | 可重組段落順序、合併拆分段落 |
| 術語與結構 | 全鎖，一字不動 | 術語鎖，段落結構大致保留 | 術語仍鎖，結構可動 |
| 空話處理 | 幾乎不刪，只清最明顯的 | 整句空話列出來建議刪，重要刪改要標示 | 直接刪並重寫承接 |
| 施事者補全 | 不主動補 | 假代理補回施事者 | 全篇統一施事者視角 |
| 適用文類 | 技術文件、公文、學術摘要、非母語稿 | blog、貼文、文案 | 使用者明說要大改的長文 |

### 適用場景

- **保守檔**：文類本身就規則化（術語密集的技術文、制式公文、有引用格式的學術摘要），或稿子是非母語、翻譯來源。這些硬改反而破壞正確性。只清掉最明顯的機械開場結尾，其餘留著。
- **標準檔**：一般 blog、社群貼文、行銷文案。改句子和段落內部節奏，整句空話列出來建議刪，動到重要內容的刪改要標示讓使用者復核。這是最常用的一檔。
- **激進檔**：只有使用者明講「大改／重寫／結構亂請重組」才用。可以動段落順序、合併或拆分段落。就算到這一檔，術語、數字、引用、命令仍然全鎖。

三檔共通：不管哪一檔，保護片段（數字、術語、引用、命令、專有名詞）都不動。激進不等於可以動事實，只是可以動結構。

## 三、保真回讀完整清單

改完，逐句對照原文，確認沒犯下面每一項。這是防編造與防改壞的最後一關。發現任一項，退回修正，不要放行。

| 檢查項 | 問自己 | 犯了怎麼辦 |
|---|---|---|
| 新增事實 | 改後有沒有出現原文沒有的事實、數字、引用、第一手經驗 | 刪掉新增物；若該處確實需要資料，標 [待查] 或 [待補] 留給使用者 |
| 施事者丟失 | 有沒有把「誰做的」改丟了（例「國家推動」改成「推動」，丟了國家） | 把施事者補回去，確認主語還在 |
| 推測變結論 | 原文是推測、可能、大概，改後有沒有變成斷定 | 把語氣還原成推測，保留「可能／應該／我猜」這類限定 |
| 術語被動化 | 為了通順有沒有把術語改成被動語態或換成非術語的說法 | 術語與其語態還原，術語一律鎖 |
| 標點轉錯 | 全半形有沒有被自動轉錯，破折號有沒有殘留，引號有沒有配對 | 全形化中文標點，清掉「——」，補齊引號 |
| 責任主體 | 有沒有把某句話的責任主體改模糊了（誰說的、誰負責、誰的觀點） | 把責任主體講清楚，別讓句子懸空沒有主人 |

回讀順序建議：先掃新增事實與施事者丟失（傷內容正確性，最嚴重），再掃推測變結論與責任主體（傷語氣誠實），最後掃術語被動化與標點（傷規範一致性）。

## 四、無源引用的三種處理

遇到「研究顯示／專家指出／根據數據」這類模糊權威且查不到具名來源，處理方式取決於當前模式與使用者選擇。三選一，不要自己編來源。

| 處理 | 用在哪 | 做什麼 | 範例 |
|---|---|---|---|
| rewrite-safe（直接刪） | audit-then-fix 模式，使用者選了改，且該句刪掉不損主旨 | 把無源的權威聲稱整句刪掉，或改寫成不依賴那個聲稱的說法 | 「研究顯示專注力只有八秒」→ 若這句只是墊場，直接刪，講你自己的重點 |
| audit-only（只標） | audit-only 模式，或使用者選了不改 | 不動原文，只在報告標出這是無源引用，附 `[無來源]` 或 `[待查]` 記號 | 報告寫：「第 2 段『研究顯示』缺具名來源，標 [待查]，建議補來源或改口」 |
| rewrite-with-placeholder（標 [待查]） | 使用者選了改，但該聲稱是主旨關鍵、刪不掉 | 保留聲稱的結構，把出處位置標成 [待查]，留給使用者補 | 「根據 [待查] 的研究，專注力大約八秒」，並在 diff 的「仍需你補」區列出 |

記號約定沿用 SKILL 第三段：`[待查]` 是查不到但理應有；`[無來源]` 是明顯自產（例作者不是研究機構卻寫「根據我們的研究」）；`[來源已揭露]` 是模糊權威但有揭露，風險降級可不處理。

底線：任何一種處理都不准把模糊權威補成看似具體的假來源（不能把「研究顯示」補成「根據 OpenAI 官方報告」）。本技能自身也守誠實邊界，不自產假數字假來源。

## 五、冷點收尾與誠實邊界的改寫範例

這一節給三種收尾方向的 before/after，都往「停在具體、不拔高、敢講缺點」的方向改。這裡吸收 Jemmy Ko 內容物理學的框架方向：讓文字停在能被指認的物理點上，而不是滑向抽象升華。

### 5.1 冷點收尾（停在物理事實或未解決問題）

改前：

> 剪輯的過程讓我明白，真正重要的不是技巧，而是我們對表達的執著與熱愛。

改後：

> 這支我調了四版轉場還是不滿意，先擱著，下一支換個節奏再試。

改動說明：砍掉「讓我明白／真正重要／執著與熱愛」這層升華，停在一個還沒解決的具體動作上。收尾不需要總結全文，停在一個真實的未完成反而更像人寫的。

### 5.2 揭露缺點（不只講好，講清楚哪裡不行）

改前：

> 這款軟體功能全面、操作直覺，是創作者的最佳選擇。

改後：

> 這款軟體我用下來，剪接和調色都夠用，但它匯出 4K 的時候風扇會狂轉，長片我還是切回舊的那套。

改動說明：把「功能全面／操作直覺／最佳選擇」這種全是優點的公關句，改成有取捨的真實評價。點出一個具體缺點（匯出 4K 時的問題）和一個實際選擇（長片切回舊軟體），可信度立刻不一樣。缺點要具體到可被指認，不要只說「也有一些不足」。

### 5.3 大聲說限制（把適用邊界講在前面）

改前：

> 這套方法適用於各種場景，能全面提升你的創作效率。

改後：

> 這套方法是我拍固定機位的口播影片摸出來的，多機位或外景我沒試過，不確定能不能照搬。

改動說明：把「適用於各種場景／全面提升」這種無邊界的宣稱，改成講清楚適用範圍和沒驗證過的範圍。誠實講限制不會削弱可信度，反而讓讀者知道你在講一個真實用過的東西，而不是背話術。

## 六、改壞的反例集

這一節列常見的改壞，讓改寫時知道哪些方向是錯的。反例的共通點：為了去 AI 味，反而傷了內容或製造新的 AI 味。

### 6.1 施事者丟失（去 AI 味時把主語一起刪了）

原文：

> 國家推動這項政策，補助分三年撥付。

改壞：

> 推動這項政策，補助分三年撥付。

為什麼壞：改寫者想精簡，把「國家」當贅字刪了。結果句子沒了主語，讀者不知道是誰推動。施事者不是贅字，是責任主體。這正好違反第三節回讀清單的「施事者丟失」項。

正確方向：主語留著，要精簡去別的地方精簡。

> 國家推這項政策，補助分三年撥。

### 6.2 把口語過度矯正成公關腔（越改越像 AI）

原文（作者原本的口語）：

> 這功能我用了兩天，坦白講有點雞肋，不太會再開。

改壞：

> 此功能經過實測，其實用價值有待商榷，使用頻率相對有限。

為什麼壞：改寫者把有溫度的口語「矯正」成看似專業的書面語，結果「有待商榷／相對有限」全是空的公關腔，反而更像 AI。去 AI 味的目標是更像人講話，不是更正式。把真實口吻磨掉是反方向。

正確方向：口語本身沒有 AI 味就別動。真要清，只清錯字或明顯口誤，語氣保留。

> 這功能我用了兩天，坦白講有點雞肋，之後不太會再開。

### 反例的共同教訓

- 精簡不能砍掉施事者、責任主體、限定語（可能、大概、我猜）。
- 口語不是缺點，去 AI 味不等於書面化、正式化。
- 每一個「改得更漂亮」的衝動，先問一句：這是去掉 AI 味，還是在製造新的 AI 味。若改後更整齊、更宏大、更像話術，就是改反了。

### 句子層五問（改單句時的定位工序）

改一個空泛句時，前面各節給的是「換成具體動詞、補回施事者」這類方向，但沒有一套逐句拆解的問法。這五問補上：拿到一個像 AI 的句子，依序問，把答案填回句子，句子就落地了。

1. 找主語：誰做了這件事。
2. 找動作：真正發生的動作，不用抽象名詞包起來。
3. 找條件：在什麼情況下成立。
4. 找限制：不適用誰、缺什麼資料、尚未測什麼。
5. 找證據：來源、截圖、數字、實測、例子。

守誠實邊界：五問裡「找證據」若原文沒有具體證據，不可自己編一個，標 `[待查]` 或 `[待補]` 交回使用者，這一條沿用前面第四節與保真回讀的規定。

### 段落層收束建議（改整段時的節奏工序）

前面談句層改寫多，段層節奏只在三檔策略和節奏勻稱度裡零星提到，沒有給一段內部的建議排列。這幾條補上：

- 第一句回答本段問題。
- 第二句補條件或原因。
- 第三句給例子或限制。
- 不要每段都用同一種句型收束。
- 如果一段只是「這很重要」，刪或改成具體後果。

這不是硬性公式，是提醒段落內要有推進與變化，避免每段同一句型收尾造成節奏過勻。若某段本來就自然，不必硬套這個順序。

### 長文處理四分級（動手前的分類工序）

前面有三檔策略（保守／標準／激進）決定改動幅度，但沒有一套「先把長文句子分堆再動手」的前置分類。長文不要一次全部洗掉，先分四類，再決定動哪幾類：

```text
必改: 明顯 AI 腔、空泛句、錯誤語域
可改: 節奏太整、轉折太制式
不改: 具體事實、引用、作者特色、SEO 必要結構
待確認: 可能要刪但牽涉作者意圖的句子
```

預設只動 `必改` 和一部分 `可改`。`不改` 對應 SKILL.md 的保護片段與各文類降級，`待確認` 對應 SKILL.md 確認閘門與 diff 的「仍需你補」區，遇到就標出來交回使用者，不自作主張。
