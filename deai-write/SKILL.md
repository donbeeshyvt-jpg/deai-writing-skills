# 從零生成沒有 AI 味的內容

## 原則

這是「生成技能」。輸入主題加素材加場景加目標讀者，輸出一篇本來就沒有 AI 味、且具備基礎寫作功力的成稿。不是事後改寫。防禦寫在生成當下，禁用句型一開始就不寫，不是先寫完再洗。

寫作即優化。內容物理學先於文采：讀者 2 秒內看不到答案就離開，眼球走 F 型（重點靠左、靠段落開頭），手機一行約 15 到 20 個中文字，大腦走省電模式只接白話。先讓內容被讀完，再談漂不漂亮。

誠實邊界是硬底線。不編造事實、數字、第一手經驗。查不到的具體資訊標 `[待補]` 或 `[待查]`，寧可留白也不填假貨。這條沒有例外。

規則會誤判，也不做身分判決。本技能不對任何文字判定「這是 AI 寫的」。短文、技術文件、公文、學術摘要、非母語中文、SEO 制式文本來就規則化，要降級處理，不硬套所有清單。生成前先看場景，再決定套哪一檔強度。

## 0. 輸入合約

開工前先收齊這幾欄。缺欄位就問，不腦補。

| 欄位 | 說明 | 缺了怎麼辦 |
|---|---|---|
| 主題 | 一句話題目 | 必問，沒主題不能生成 |
| 素材 | 截圖 / 連結 / 口述 / 檔案 / 舊文 / 數據 | 沒素材就走「知識層」，具體資訊全標 `[待補]` |
| 場景 | blog / social / docs / email / landing / script / other | 判不出來就用 §1 的信號自己判，並回報判斷 |
| 目標讀者 | 誰會讀、他的專業程度、他想解決什麼 | 必問，決定白話深度與術語註解密度 |
| 目標 | 要讀者讀完做什麼（搜到答案 / 被說服 / 學會操作 / 記住觀點） | 必問，決定骨架與收尾 |
| 風格輸入（可選） | voice profile 或短 prompt（來自 deai-voice） | 沒有就用通用自然文風；有就套該聲音生成 |

素材分級（決定每一句可以寫多滿）：

| 級別 | 標籤 | 可以寫成 | 不可以寫成 |
|---|---|---|---|
| 作者本人 | `[本人]` | 觀點、感受、經歷、素材裡有的實測數據 | 素材外的因果、精確數字 |
| 官方文件 | `[官方]` | 明文寫在官方頁的規格、政策 | 憑印象補的版本、價格 |
| 媒體報導 | `[媒體]` | 具名來源的轉述 | 當成官方定論 |
| 第三方研究 | `[研究]` | 標注來源與時點的統計 | 當成平台官方規則 |
| 推算 | `[推算]` | 明講「這是估算」 | 當成已確認事實 |
| 待查 | `[待查]` / `[待補]` | 先留白標記 | 假裝已確認 |

同一段不混級。經驗、官方、推算要分段或明講。

## 1. 場景校準

先判場景，再決定強度。每種場景的預設檔位、保護重點、可放寬的規則都不同。

| 場景 | 信號 | 強度檔 | 保護重點 | 放寬 |
|---|---|---|---|---|
| blog | 部落格、教學、觀點長文 | 標準 | 直答前置、SEO 結構 | 可較口語、可自嘲 |
| social | 貼文、限動、短評，通常低於 500 字 | 輕量 | 一個核心點、開頭鉤子 | 不要求段落非等長、不要求 FAQ |
| docs | 操作說明、技術文件、API 文檔 | 保守 | 術語穩定、步驟編號、可複現 | 不強行口語化、不硬塞幽默、術語不改 |
| email | 通知、提案、回覆 | 標準 | 第一句講事、語域對收件人 | 短，不要求鉤子公式 |
| landing | 產品頁、銷售文案 | 標準偏保守 | 賣點具體、CTA、不破壞轉換 | 保留必要重複，不為多樣化砍賣點 |
| script | 口播稿、影片腳本、對白 | 標準 | 口語節奏、可念出來、停頓點 | 允許口語碎句、允許重複強調 |
| other | 判不出來 | 標準 | 先問使用者，或用最接近的一檔 | 回報你選了哪一檔 |

降級判斷（命中就降強度，不硬判 AI 味規則）：

- 全文低於 500 字：只守「開頭鉤子」「不用禁用句型」「標點」三條，其餘放行。
- 技術文件 / 公文 / 學術摘要：術語與格式優先，只清「開場套話」與「升華結尾」兩處。
- 非母語中文寫手的素材：不強行改他的用詞習慣，重點放內容密度與邏輯。
- SEO 制式文：保留 title、H2、前 100 字的搜尋意圖結構，只在段落內調節奏。

細節看 `references/scene-calibration.md`。

## 2. 生成前決策塊

場景定了，動筆前一次輸出這幾欄，全部定案再寫。這一步不寫給讀者看，是給自己的施工圖。

```
場景 / 強度檔:      （§1）
主 query / 意圖:     讀者會怎麼搜，資訊型 / 商業調查型 / 交易型（blog、landing 必填）
目標讀者白話深度:   給誰讀，術語要不要註解，預設向 5 歲看齊，技術或專業讀者按 §1 放寬
骨架型:             §3 選一型
開頭鉤子候選:       低於 20 字、破痛點那句
直答句:             第一段要能被獨立摘取的答案句
風格輸入:           有無 voice profile；有就抄關鍵規則到這裡
必問作者清單:       具體數字、時間點、結果、踩過的坑，拿不到標 [待補]
來源 / 查證:        外連官方來源 + [待查] 清單
禁用檢查:           本次會不會誤觸某禁用句型，先想好替代寫法
```

70/30 調研寫作比：先做報告再寫。七成力氣在查事實、看 SERP 前三名、找內容空隙；三成力氣在寫。素材不夠就先補素材，不要用漂亮句子蓋過空洞。

## 3. 基礎寫作技藝（生成當下就照做）

每個技藝的施工細節、對照庫與範例在 `references/writing-craft.md`。

### 3.1 結構骨架

先搭骨架再填肉。骨架本身就是人類邏輯：脈絡到具體細節到後果，不是「泛論、展開、拔高總結」。

| 骨架型 | 適用 | 中段順序 |
|---|---|---|
| 解答型 | 資訊型 query | 直答、為什麼、怎麼做、限制條件 |
| 工具型 | docs、教學 | 前置、編號步驟、常見狀況排除、實測紀錄（沒素材就省） |
| 比較型 | 商業調查 query | 評估標準、A 情境、B 情境、對照表、誰不適合 |
| 敘事型 | 日誌、觀點 | 場景事實、展開轉折、冷點收尾 |
| 說服型 | landing | 痛點、賣點具體化、證據、反對意見處理、CTA |

開場（進正文前，2 到 3 段）：

- P1：鉤子加直答。1 到 2 句痛點破題，同段內必須出現直答句。全段 80 到 135 字。
- P2：「這篇處理什麼、不處理什麼」的範圍界定。
- 每個小節標題前留一行呼吸線（前後空行的 `---`）。

收尾：冷點收尾。停在冷靜的物理事實或還沒解決的問題，不拔高人生意義。

### 3.2 長方形排版

- 手機每行約 15 到 20 個中文字，視覺呈窄長矩形，誘導視線垂直下滑。
- 每段 2 到 3 行，80 到 150 字，絕不超過 200 字。
- 段落長度非等長。禁連續 3 段都落在同一個字數區間，長短混合。
- 金句粗體全篇 3 到 4 處為上限，句式每次要變，絕不每節一顆同模板，禁每段粗體。
- 正文零 emoji。

### 3.3 具體化（400 萬單位感官捕捉）

把抽象形容詞換成物理參數、品牌型號、具體數值、動作、感官。

| 抽象 | 改成 |
|---|---|
| 很擠 | 尖峰七點半的板南線，門一開只能側身塞進去 |
| 超香 | 一進門就是現磨曼特寧那股焦糖味 |
| 好累 | 眼皮撐到早上四點，第三次泡咖啡 |
| 至關重要 | 這步漏了，後面整批資料要重跑 |
| 賦能 / 打造 | （拆成實際動作流程，不用這兩個詞） |
| 這個工具很強大 | 匯入 10GB 檔案，3 秒內搜到第 14 個檔 |

每篇至少 3 處具體化。只換同義詞不算（「重要」改「關鍵」不算具體化）。

### 3.4 系統 1 白話

- 白話深度預設向 5 歲看齊，再按目標讀者上調。給一般讀者就寫生活白話，技術或專業讀者按 §1 放寬，但仍不用學術腔。
- 優先動詞加具體名詞。每句自問：主語是誰、動作是什麼、何時、多少、誰能用誰不能用。
- 禁名詞化。「進行了一次調查」改「我測了 5 個」。
- 剔除濫用的轉折詞。真的邏輯轉折才留「但」，沒有邏輯需要就刪。禁「其實 / 說到底 / 真正的」當口頭禪開頭。
- 專有名詞或英文詞首次出現用（）白話註解一次，同一個詞後續直接用，不重複註解。重複括號註解是白話化長出來的新 AI 味。

### 3.5 鉤子

第一句低於 20 字，破痛點或戳現象。同段內必出現直答句。

禁開場套話：「在當今⋯時代」「隨著⋯快速發展」「讓我們一起來看看」「本文將深入探討」「如何⋯已成為重要議題」。

### 3.6 七三調研與 SEO 意圖

- 關鍵字埋放權重由高到低：標題、內連錨點、H 標籤、內文前 100 字。
- 搜尋意圖三型：資訊型（為什麼 / 如何 / 是什麼）寫解答文；商業調查型（推薦 / 比較 / TOP）寫比較文；交易型（品牌名 / 購買）寫導購。
- 一頁一意圖，所有 H2 繞同一個核心 query。
- 長尾優先。主詞排不動先攻 3 詞以上長尾。
- 要做到意圖確認、既有稿 SEO 化、社群與電子報平台適配，改用 `deai-writing-seo`。

### 3.7 E-E-A-T 與揭露缺點

- 直答前置，先給答案，後說但書與不適用條件。
- 大聲說出限制。每篇都有「但⋯」句子：「可以。但前提是⋯」「這不是完整測試，只是這次素材能確認的結果」。
- 有真實素材時，加 1 個作者的失敗或笨拙細節：「我踩過⋯坑」「試了 4 遍才搞懂」。禁編造不存在的糗事。
- 揭露缺點會提高信任，不是減分。

### 3.8 冷點收尾

最後一句是冷靜的物理觀察或事實陳述，或還沒解決的問題。

- 可以：「就這樣轉了三圈」「我還沒弄懂它什麼時候會改」「目前只在這個版本測過」。
- 禁止：「這讓我想起⋯」「其實這就是人生」「願我們都能⋯」「未來可期」。

### 3.9 幽默公式（可選，不硬塞）

只在場景與語域容許、且素材撐得起時用。理性堆疊型：具體小觀察、冷靜拆解、荒謬演算法、不予置評。荒謬來自語氣和內容的反差，不是加感嘆號或網路梗。

docs、公文、嚴肅主題不用幽默。不確定就不用。

## 4. 生成時 anti-slop 防禦

這些句型一開始就不寫，不是寫完再洗。生成每一段時，腦中先過這張禁用清單。完整表與「聚集才算問題」的判準在 `references/banned-patterns.md`。

### 4.1 禁用句型（見到自己要寫就換掉）

| 類別 | 禁用 | 改成 |
|---|---|---|
| 工整對稱 | 不僅⋯更是⋯ / 不是 X 而是 Y / 透過 A 達成 B | 直接說 Y，刪掉前半句的鋪墊 |
| 假深度 | 這不只是 A，更是 B | 直接講那件事 |
| 升華總結 | 這讓我想起 / 其實這就是 / 歸根結底 | 停在具體事實（冷點收尾） |
| 宏大開場 | 在當今⋯時代 / 隨著⋯發展 | 第一句直接破題 |
| 空泛重要性 | 至關重要 / 不可或缺 / 意義重大 | 講不做的具體後果 |
| 模糊權威 | 專家指出 / 研究顯示 / 業界普遍認為（無來源） | 具名來源加年份，或標 [待查]，或寫「我的觀察」 |
| 翻譯腔 | 透過⋯來實現 / 對於⋯而言 | 拆成主動句，主語加動詞 |
| 假口語 | 真的太香 / 直接封神 / 寶藏（無場景） | 給具體場景細節 |
| 過場套話 | 值得注意的是 / 不難發現 / 接下來讓我們 / 首先其次最後 | 刪掉，直接講內容 |
| 金句收尾 | 段末掛「⋯展現了⋯」「⋯反映出⋯」 | 刪掉尾巴，句子在事實處停 |

### 4.2 禁用標點與結構

- 禁破折號 `——`。要停頓用逗號，要補充用括號或另起一句。
- 中文正文一律全形標點 `，。：；！？（）「」`。禁半形 `, . : ;` 混進中文。英文與數字前後留半形空格。
- 禁連續等長段落。禁每段粗體。禁三連排比（除非內容真的是三項並列）。
- 假權威數字禁止。所有統計、百分比、排名都要帶來源等級。無法驗證改 `[待補]`。嚴禁自產虛假數字。

### 4.3 生成時的正向做法（不只是躲禁令）

- 句長變異：一段內同時有短句（開頭 10 字以內）和長句（25 字以上）。禁全段句子都 15 到 20 字均勻。
- 段落開場必直答：每個 H2 下第一句先回答核心問題，不繞路做背景介紹。
- 每個主張後帶條件：何時（2026 年 6 月、這次測試）、多少（具體數字）、誰能用、誰不能用。
- passage 自包含：每節脫離上下文可讀，不用「這個工具」代稱，實體全名每節出現 1 次。
- 重複關鍵詞而非同義詞輪轉：不要「開發者、工程師、實踐者、建構者」繞圈，該重複就重複。

## 5. 誠實邊界

- 經驗層（「我做了 / 我測到 / 我覺得」）：只准來自 `[本人]` 素材，逐字抽引後改寫，零延伸。
- 知識層（規格 / 條文 / 公開事實）：可用可驗證公開資訊，每個主張掛得出來源等級，查不到標 `[待查]` 不寫。
- 缺口一律標記，不用擬真數字填空。`[待補:具體幾次]`、`[待查:官方定價]`。
- 明示邊界句是信任資產：「這部分我沒實測過，以官方文件為準。」鼓勵使用。

> 這是本技能最重要的一條。AI 自產的具體數字是最危險的假貨形態，寧可留白。

## 6. 可直接貼的系統提示詞

把下面這段整段貼給任何 AI 當開場設定，它就會照本技能生成。使用者也可以照著這段自己逐步執行。這是 blog 預設版；docs、social 等其他場景的成品替換版見 `references/self-check-and-prompt.md`。

```text
你要從主題和素材直接生成一篇繁體中文成稿，本來就沒有 AI 味，而且有基礎寫作功力。不是先寫完再改。

先跟我確認五件事，缺了就問，不要自己編：主題、素材（以及每份素材是我本人的還是官方的還是待查的）、場景（blog / social / docs / email / landing / script / other）、目標讀者、我要讀者讀完做什麼。若我有指定某人的語氣（voice profile），也一併收進來當風格約束。

收齊後，先只輸出一份施工圖給我看：場景與強度檔、讀者白話深度、骨架型、開頭鉤子候選、第一段直答句、風格輸入、必須問我補的清單、來源與待查清單。我確認後你才寫全文。

寫全文時逐段守這些規則：
一、開頭第一句 20 字以內破痛點，同一段內出現能被獨立摘取的直答句。
二、每段 80 到 150 字，2 到 3 行，段落長度長短交錯，不要連續等長。手機一行約 15 到 20 字。
三、把抽象形容詞換成具體數字、品牌型號、動作、感官，全篇至少 3 處。很擠改成具體時間地點，超香改成品牌和氣味。
四、白話到我的讀者能懂，預設向 5 歲看齊，優先用動詞加具體名詞，剔除沒有邏輯必要的轉折詞。專有名詞第一次出現用括號白話註解一次，後面直接用。
五、每個主張後面帶條件：何時、多少、誰能用、誰不能用。
六、大聲說出限制，用「可以，但前提是」這種句子。有真實素材時加一個我的失敗或踩坑細節，沒有就不要編。
七、結尾停在冷靜的事實或還沒解決的問題，不要拔高人生意義，不要金句總結。

這些句型一開始就不要寫：不僅更是、不是X而是Y、透過A達成B、值得注意的是、總而言之、讓我們深入探討、在當今時代、隨著快速發展、至關重要、專家指出（沒來源）、這讓我想起、其實這就是。禁破折號，中文用全形標點，禁每段粗體，禁三連排比。

誠實邊界：不要編造事實、數字、我的第一手經驗。查不到的具體資訊標成 [待補] 或 [待查]，寧可留白不要填假的。

寫完後自己跑一次自檢，沒過就自己重生成，不要把沒過的稿子交給我。
```

docs 場景要把場景那句換成 docs，並加一句：「術語不要改，不要硬塞口語和幽默，步驟用編號清單。」social 場景把長度改成「全文低於 500 字，只守鉤子、禁用句型、標點三條」。

## 7. 生成後自檢閘門

寫完先自己跑這道迷你 audit。掃描順序：每段生成後立刻掃該段，全篇寫完再總掃一次。任一項不過就改該處再重掃，不要把沒過的稿子交出去。這是生成技能自帶的品管，不是叫使用者去跑別的技能。

11 項生成時檢查清單（逐項對，每項判準見 `references/self-check-and-prompt.md`）：

1. 第一句低於 20 字破痛點，第一段有直答句。
2. 本段長度和上一段不同。
3. 段內有短句也有長句。
4. 沒有抽象形容詞未具體化。
5. 每個主張帶時間、數字或條件。
6. 沒有無來源的權威聲稱。
7. 動詞在前，沒有名詞化堆疊。
8. 沒有濫用轉折詞。
9. 沒有對稱排比句。
10. 沒有段末金句濫用，收尾是冷點。
11. 標點全形，零破折號，沒每段粗體。

迷你 5 維自評（各給低 / 中 / 高風險，任一「高」就重生成該面向）：

| 維度 | 看什麼 | 高風險長怎樣 |
|---|---|---|
| 直接性 | 有沒有一直暖場鋪陳 | 開場整段都是預告，沒有內容 |
| 具體性 | 有沒有人物、動作、時間、數字 | 抽象名詞堆疊，找不到施事者 |
| 節奏 | 句長段長轉折是不是太平均 | 連續 3 段等長、每段粗體 |
| 來源感 | 有沒有模糊權威、假客觀 | 權威聲稱無來源又缺例子 |
| 個人聲音 | 有沒有立場、限制、取捨、真實觀察 | 全文無「但」、無限制、無取捨 |

降級提醒：短文、docs、公文、學術摘要、非母語素材、SEO 制式文，自檢只跑「禁用句型」「標點」「開頭鉤子」三項，5 維不硬評。

自檢過了就交稿。若要獨立複審，交稿後可再過 `deai-guard` 做一次不偏袒的檢查（見 §10）。

## 8. 輸出格式

預設兩階段交付：

1. 先出施工圖（§2 決策塊），交人類確認。
2. 確認後才寫全文，附 `[待補]` / `[待查]` 清單。

使用者明確要求「直接寫全文」可跳過階段 1，但全文仍必須保留所有缺口標記。

全文交付時附一行自檢結果：`自檢：11 項通過，5 維無高風險，待補 2 處（已標於文中）`。

不自行 commit、push、部署、發佈。這些一律另外取得授權。

## 9. 禁止事項

- 不做事後改寫。這是生成技能：既有文章要去 AI 味用 `deai-guard`，要 SEO 化用 `deai-writing-seo`。
- 不編造事實、數字、作者第一手經驗。缺口標 `[待補]` / `[待查]`。
- 不硬塞幽默。docs、公文、嚴肅主題不用。
- 不破壞語域。給誰讀就用誰的語域，不把技術文寫成小紅書。
- 不破壞 SEO 意圖。不為了口語化砍掉 title、H2、編號步驟、FAQ 的結構。
- 不用破折號 `——`，不用半形標點混中文，不每段粗體。
- 不對任何文字下「一定是 AI 寫的」這種身分判決。
- 不把沒過自檢的稿子交出去。

## 10. 與其他技能搭配

| 技能 | 分工 | 何時接手 |
|---|---|---|
| `deai-write`（本檔） | 從零生成沒有 AI 味的成稿 | 有主題加素材，要寫新內容 |
| `deai-guard` | 檢查既有文字，出證據化報告，問過使用者才改 | 生成後想要獨立複審，或救別人寫的 AI 味舊稿 |
| `deai-voice` | 提煉某人口吻成三檔角色卡（說話格式可直接貼） | 要讓生成貼合特定人的口吻，產物填進本技能 §0 的「風格輸入」欄 |
| `deai-writing-seo` | 意圖優先的 SEO 寫作與改寫，新寫或改既有稿都行 | 文章要排上搜尋、或既有稿要 SEO 化。它可以把 SEO 藍圖交給本技能生成，這時段落字數當參考帶、不強迫加失敗細節，以它的規矩為準 |

典型串接：`deai-voice` 產出語氣檔，填進本技能 §0 風格輸入生成，再用 `deai-guard` 獨立複審。要排名的文章改走 `deai-writing-seo`，一樣可以帶口吻，最後用 `deai-guard` 複審。
