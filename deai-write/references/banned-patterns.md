# 禁用句型與替代寫法全表

這是 `deai-write` §4 的展開版，也是這個技能包最常被載入的參考檔。生成每一段之前，腦中先過一次這張表。這裡不做「這是不是 AI 寫的」的身分判決，只提供「見到自己要寫、就換掉」的操作清單。

## 一、聚集原則：先讀這段再看表

單一特徵不算證據，多特徵疊加才算。

一句「但是」很正常，一個破折號的替代裡偶爾漏一個逗號也不致命。真正露餡的是同一段裡，工整對稱句、空泛升華、無來源權威、每句等長這幾樣一起出現。判斷時看的是密度和共現，不是抓單點。

所以底下把禁用句型分三層，對應三種不同的處理力度。

### Tier 1 永遠不寫

這幾類只要出現一次就是硬傷，不看上下文，直接換掉。

- 不僅⋯更是⋯（以及所有「不僅 A，更 B」的變體）
- 不是 A 而是 B（用來假裝有深度的轉折）
- 值得注意的是（以及「不難發現」「顯而易見」這類過場提示）
- 在當今⋯時代 / 隨著⋯的發展（宏大開場）
- 破折號 `——`

這五類是最強的 tell，出現一個就足以讓熟練讀者起疑，不需要別的特徵陪襯。

### Tier 2 聚集才算問題

這一層的句型單獨出現是正常中文，疊起來才是 AI 味。

- 轉折詞「但 / 然而 / 其實」：單一個「但」是正常的邏輯轉折。同一段疊三個以上，又搭配對稱句式，才算問題。
- 排比：真的有三項並列時，三連句是對的。沒有三項內容卻硬湊成三段等長排比，才要拆。
- 「這讓我想起 / 說到底 / 真正的」當開頭：偶爾一次是口語，每個小節開頭都這樣起手才是套路。

判準：這一層看的是「同段或鄰近段落的重複疊加」，不是單句。抓到一個不動手，抓到一叢才拆。

### Tier 3 密度過高才標

這一層完全是統計性的，看的是全篇比例，不是任何單句。

- 轉折詞頻率：整篇轉折詞（但、然而、其實、不過、儘管）出現得比一般人說話密很多，才調。多密算密沒有固定數字，這裡是質性判斷，靠讀出來的節奏，不是數出來的次數。
- 粗體密度：全篇粗體超過骨架建議的 3 到 4 處，或每個小節都固定掛一顆粗體金句，才算過密。
- 段落等長：連續三段以上落在同一字數區間，視覺上像被切齊，才處理。

Tier 3 不對單段扣分，只在總掃時看全篇分布。

## 二、禁用句型三欄表：偵測、為什麼像 AI、替代寫法

每一列給「怎麼偵測到」「為什麼讀起來像 AI」「改成什麼」，多數附 before/after 具體中文範例。

### 工整對稱

| 欄 | 內容 |
|---|---|
| 偵測 | 出現「不僅⋯更⋯」「不是 A 而是 B」「透過 A 達成 B」這種前後對仗的框架 |
| 為什麼像 AI | 對稱結構是模型最愛的排版慣性，讀起來平整、沒有一個真人講話會這麼工整 |
| 替代 | 刪掉前半句鋪墊，直接講後半句要說的那件事 |

- before：這不僅是一次更新，更是一場體驗的重塑。
- after：這次更新把載入速度從 8 秒砍到 2 秒。

### 假深度

| 欄 | 內容 |
|---|---|
| 偵測 | 「這不只是 A，更是 B」用抽象名詞往上墊一層 |
| 為什麼像 AI | 用拔高代替具體，B 通常是空詞（意義、態度、選擇），沒有新資訊 |
| 替代 | 直接講那件事本身，不加意義層 |

- before：選這台相機，不只是選一個工具，更是選一種生活態度。
- after：這台相機重 380 克，塞得進外套口袋，我通勤時整天帶著也不累。

### 升華總結

| 欄 | 內容 |
|---|---|
| 偵測 | 段末或結尾出現「這讓我想起」「其實這就是」「歸根結底」「說到底」 |
| 為什麼像 AI | 硬把具體經驗抽象成人生道理，是模型收尾的預設動作 |
| 替代 | 停在具體事實，用冷點收尾（見 SKILL §3.8） |

- before：泡了第三次咖啡，其實這就是成年人的日常吧。
- after：泡了第三次咖啡，天已經亮了。

### 宏大開場

| 欄 | 內容 |
|---|---|
| 偵測 | 第一段出現「在當今⋯時代」「隨著⋯的發展」「如何⋯已成為重要議題」 |
| 為什麼像 AI | 用時代背景暖場，把讀者要的答案推到很後面 |
| 替代 | 第一句直接破痛點，同段給直答句 |

- before：隨著遠端工作的普及，如何提升線上會議效率已成為重要議題。
- after：一場一小時的會議，前 15 分鐘都在等人到齊。這篇講怎麼把它壓到 40 分鐘結束。

### 空泛重要性

| 欄 | 內容 |
|---|---|
| 偵測 | 「至關重要」「不可或缺」「意義重大」「舉足輕重」 |
| 為什麼像 AI | 只宣稱重要，不說重要在哪，讀者無從驗證 |
| 替代 | 講不做這件事的具體後果 |

- before：定期備份至關重要。
- after：這步漏了，硬碟掛掉那天，你三年的檔案一起沒。

### 模糊權威

| 欄 | 內容 |
|---|---|
| 偵測 | 「專家指出」「研究顯示」「業界普遍認為」後面沒有具名來源 |
| 為什麼像 AI | 借一個查不到的權威撐場，是最常見的假客觀 |
| 替代 | 給具名來源加年份，或標 `[待查]`，或老實寫「這是我的觀察」 |

- before：研究顯示，多數使用者會在 3 秒內離開。
- after：這個 3 秒的說法我還沒找到原始出處，先標 `[待查]`。我自己看後台，停留少於 5 秒的訪客佔大宗。

### 翻譯腔

| 欄 | 內容 |
|---|---|
| 偵測 | 「透過⋯來實現」「對於⋯而言」「基於⋯的考量」 |
| 為什麼像 AI | 英文語法直翻的痕跡，主語被藏在介系詞後面 |
| 替代 | 拆成主動句，把主語和動詞擺到前面 |

- before：透過導入自動化流程來實現效率的提升。
- after：我們把出貨流程自動化，人工揀貨那段砍掉，一單快 20 分鐘。

### 假口語

| 欄 | 內容 |
|---|---|
| 偵測 | 「真的太香」「直接封神」「寶藏」「絕絕子」出現，但沒有任何具體場景 |
| 為什麼像 AI | 貼社群用語當親近感，卻沒有支撐它的細節，空有語氣 |
| 替代 | 補上具體場景細節，讓「香」有來源 |

- before：這家咖啡真的太香了，寶藏店！
- after：一推門就是現磨曼特寧那股焦糖味，老闆手沖，一杯要等六分鐘。

### 過場套話

| 欄 | 內容 |
|---|---|
| 偵測 | 「值得注意的是」「不難發現」「接下來讓我們」「首先其次最後」 |
| 為什麼像 AI | 純過場，不帶任何內容，只是模型在換段時的填充 |
| 替代 | 整句刪掉，直接講下一件事 |

- before：值得注意的是，這個設定預設是關閉的。
- after：這個設定預設關閉，要自己去開。

### 金句收尾

| 欄 | 內容 |
|---|---|
| 偵測 | 段末掛「⋯展現了⋯」「⋯反映出⋯」「⋯詮釋了⋯」 |
| 為什麼像 AI | 每段都要升華成一句金句，是最典型的模板尾巴 |
| 替代 | 刪掉尾巴，句子停在事實那裡 |

- before：這個小細節，展現了品牌對使用者的用心。
- after：這個按鈕被挪到了拇指搆得到的地方。

### 假代理（無生命主語配人類動詞）

| 欄 | 內容 |
|---|---|
| 偵測 | 主語是抽象物（數據、市場、趨勢、時代），動詞卻是人才能做的（告訴、提醒、呼喚、見證） |
| 為什麼像 AI | 把判斷責任推給沒有生命的主語，句子聽起來客觀，其實在藏施事者 |
| 替代 | 把真正做判斷的人擺回主語 |

- before：數據告訴我們，這個族群更在意價格。
- after：我讀完後台數據後判斷，這個族群更在意價格。
- before：時代呼喚著新的解決方案。
- after：（整句刪掉，直接講那個方案是什麼、誰做的。）

## 三、中文特有 tell 與地區權重

以下是中文語境專屬的露餡點。同一個詞在不同場景不同地區的份量不一樣，要按場景調權重，不是一刀切。

| 類型 | 典型詞 | 為什麼像 AI | 替代方向 |
|---|---|---|---|
| 翻譯腔 | 透過⋯來實現、對於⋯而言 | 英文語法直翻 | 拆主動句 |
| 公關腔 | 打造、賦能、生態、降本增效、抓手、閉環 | 商業簡報詞，空有動勢沒有動作 | 拆成實際做了什麼 |
| 小紅書假親近 | 真的太香、寶藏、絕絕子、誰懂啊 | 社群套語當親近感，缺具體 | 補場景細節 |
| 公務腔 | 據此、茲、鑑於、爰、俾 | 公文腔混進一般文，語域錯位 | 換成日常說法 |
| 空泛鼓勵 | 美好未來、共創、攜手、賦予無限可能 | 標語式收尾，不指涉任何具體事 | 刪掉，或改成一件具體的下一步 |

before/after 範例：

- 公關腔：before「我們致力於打造賦能開發者的生態」→ after「我們做了一套 API，開發者接上去就能直接調用金流，不用自己寫串接」。
- 公務腔：before「鑑於使用者反映甚多，爰予調整」→ after「很多人反映這點難用，所以我們改了」。
- 空泛鼓勵：before「讓我們攜手共創美好未來」→ after（刪掉，或改成「下一版預計 8 月上，會補上匯出功能」）。

### 地區權重差異

同一批詞，落地時要看讀者在哪。

- 「打造 / 賦能 / 生態」在中國大陸的商業語境是日常用詞，用了不見得像 AI；在台灣一般讀者眼中偏簡報腔，警覺度該調高。
- 「絕絕子 / 寶藏 / 誰懂啊」是小紅書、抖音世代的社群用語，對年輕社群讀者是自然的，對商業客戶或年長讀者是出戲的。
- 公務腔（茲、爰、鑑於）在正式公文裡是規範用語，不是 tell；混進部落格或貼文才是語域錯位。

所以這張表不是黑名單，是權重表。按 SKILL §1 的場景和目標讀者調整每個詞的扣分力度，別把中國商業文的正常用詞當成台灣部落格的硬傷，反之亦然。

## 四、標點硬規則

這一段沒有灰帶，逐條照做。

### 全形對照

中文正文一律用全形標點。半形標點不准混進中文句子。

| 該用（全形） | 不准用（半形混中文） |
|---|---|
| ，。 | , . |
| ：； | : ; |
| ！？ | ! ? |
| （） | () |
| 「」 | "" 或 '' |

### 破折號的三種替代

禁用破折號 `——`。要停頓或補充時，按語意選一種替代。

| 原本想用破折號做什麼 | 替代 | 範例 |
|---|---|---|
| 表停頓、語氣一轉 | 逗號 | before「他終於來了——遲到了一小時」→ after「他終於來了，遲到了一小時」 |
| 補充說明、插一句 | 括號 | before「這台機器——就是去年那台——又壞了」→ after「這台機器（就是去年那台）又壞了」 |
| 引出一整句展開 | 另起一句 | before「答案只有一個——時間不夠」→ after「答案只有一個。時間不夠」 |

### 英數與中文之間留空格

中文與英文、中文與數字之間，留一個半形空格。標點旁邊不用再補空格。

- before：使用React18和Node20。
- after：使用 React 18 和 Node 20。
- 例外：緊貼全形標點時不加空格，例如「（React 18）」的括號內外不再補空格。

## 五、不是 tell 的情況（避免誤判）

規則會誤判。以下這幾種「看起來中招、其實正常」的情形不扣分，硬套清單反而會把好文章改壞。

- **SEO 標題重複關鍵字**：搜尋頁本來就靠關鍵字重複命中意圖。標題、H2、前 100 字重複同一個主詞是刻意的結構，不是詞窮，不要為了「多樣化」拿同義詞去換掉它。
- **技術文件穩定術語**：docs 要求同一個概念從頭到尾用同一個詞，讀者才不會混淆。這裡的「重複」是正確做法，不是 AI 味。API 名、參數名、產品名一律不換詞。
- **非母語寫手的「透過⋯實現」**：如果素材來自非母語中文寫手，「透過⋯來實現」可能只是他的真實用詞習慣，不是模型生成。按 SKILL §1 降級處理，重點放內容密度和邏輯，別去改他的用詞人格。
- **短文本來就簡潔**：低於 500 字的貼文，句子短、資訊密、沒有鋪陳，是對的。不要因為它「不夠有起承轉合」就當成機械感，短就是它該有的樣子。
- **真的有三項並列時的三連句**：內容確實是三個平行項目（三個步驟、三個原因），寫成三段是對的。只有「沒有三項內容卻硬湊三段對稱」才是要拆的排比。

判準一句話：先確認它是不是那個場景本來就該有的樣子，再決定動不動手。誤判的成本，有時比漏抓還高。

## 附：三層速查

| 層級 | 判斷方式 | 動作 |
|---|---|---|
| Tier 1 | 單句就中，不看上下文 | 見到就換 |
| Tier 2 | 同段或鄰段疊加多個才算 | 抓叢不抓點 |
| Tier 3 | 全篇密度統計 | 只在總掃時看分布 |
