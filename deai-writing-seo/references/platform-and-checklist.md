# 平台適配與產出前檢查

這是 deai-writing-seo 第 7 關與第 8 關的展開版。前半管「同一篇內容在不同平台怎麼調」，後半是出稿前的最終驗收表。

## 一、平台分流的大原則

- 社群是推播（內容半衰期短、靠演算法推薦），官網是拉動（讀者帶著問題來搜，內容壽命以年計）。深度長青內容的家在自己控制的網站；社群發摘要與鉤子，導流回官網。
- 平台適配是最後一關（優先序第 7 層），不得為了平台格式改變原意、犧牲準確性。

## 二、官網長文排版

- 自然短段落，段首放該段關鍵資訊（配合 F 型視線）。
- 必要的小標題（H2 與 H3 對應讀者的真問題）、適量條列、足夠留白。
- 手機端視覺呈窄長塊狀（長方形方向），不是滿版文字牆。
- 這些是質性方向：不固定每段幾行、不刻意隨機化段落長度、不把整篇切成詩。內容需要長段落交代因果時，就讓它長。

## 三、社群貼文適配

- 前段迅速讓目標受眾對號入座（第一行就知道這篇在跟誰說話），但不用誤導、誇大或與正文不符的開頭。
- 保留作者原本的換行習慣、標點習慣與 emoji 使用頻率，除非它們確實妨礙閱讀。
- 帶外部連結時，連結與貼文語意要高度相關，別在無關貼文裡硬塞連結。
- 內容需符合帳號的核心定位（長期發什麼領域，就別突然跳去無關領域蹭熱度）。

### 社群演算法檢核清單（推測性，先讀聲明）

**聲明：以下檢核來自平台專利文件與從業者經驗歸納，未經平台官方完整證實，屬推測性參考。用它們當「檢查方向」可以，不得在產出或對使用者的說明裡把它們寫成已驗證的事實。沒有把握時，回到四個可靠依據：閱讀體驗、語意清晰度、內容相關性、受眾匹配。**

| 檢核方向 | 看什麼 |
|---|---|
| 語意清晰度 | 開頭能否讓人（與機器）快速辨識這篇在講什麼、給誰看 |
| 低品質訊號 | 有沒有農場式標題、空洞內容、過重 AI 味 |
| 定位一致性 | 內容是否符合帳號長期經營的領域 |
| 同好共鳴點 | 有沒有讓同領域讀者想留言、轉發的切入點 |
| 連結相關性 | 外連與內文的語意關聯是否夠高 |

### 社群診斷輸出格式（局部微調型任務用）

1. **核心意圖推測與確認**：推測目的與預期互動效果，請使用者糾正。
2. **診斷**：依上表列風險與亮點。
3. **局部微調建議**：指出具體哪句要動、為什麼、改了怎麼幫助預期效果。
4. **最終微調版**：可直接發布的版本，語氣與原版高度一致。

極簡修改原則全程生效：只動有問題的局部，不整篇重寫（細則見 `intent-and-rewrite.md` 第四節）。

## 四、電子報適配

- 開頭像寫信報近況或共感提問，中段內容主體，結尾約下次或喊訂閱。
- 標點與 emoji 比社群收斂。
- 主旨行比照標題技術：重點前置、不騙開信。

## 五、產出前檢查表（五組，逐項過）

任何一項不過，回對應關卡修，不硬出。

### 事實與意圖
- 是否保留原始目的與立場。
- 是否新增了未提供或無法確認的事實。
- 是否把推測寫成事實（含演算法規則）。
- 是否缺少必要前提、限制或來源。
- 不可改動清單（數據、步驟、條款、立場、慣用語）是否原封未動。

### 語言
- 是否存在沒有資訊量的程度修飾。
- 是否用抽象評價代替判斷依據。
- 是否把必要的否定、時間、範圍、不確定性刪掉了。
- 是否只是把抽象內容改成另一種抽象詞性（名詞化轉移）。
- 是否有過度正式、客服式或宣傳式措辭。
- 是否踩到 `banned-patterns.md` 的禁用句型（破折號、工整對稱、升華收尾、模糊權威）。

### 結構
- 是否先回答核心問題（2 秒內看得到答案）。
- 是否每段都增加新資訊或推進內容。
- 是否有重複總結、制式過場、無功能結尾。
- 是否出現大量相同長度與結構的句子。
- 是否為了自然感故意破壞文法與邏輯。

### SEO 與平台
- 是否符合主要搜尋或閱讀意圖（內容形式對得上第一頁）。
- 是否聚焦單一核心主題。
- 關鍵字是否自然、沒有堆砌、擺對權重位置。
- 標題、開頭與正文是否一致（不騙點擊）。
- 排版是否符合實際發布平台。
- 是否為了演算法猜測犧牲了內容品質。

### 人味
- 是否保留作者獨有的觀察與判斷。
- 是否捏造了經驗、缺點、情緒或生活細節。
- 是否把作者改成了通用的成熟文風（最小干預失守）。
- 讀起來是否像針對當前題目寫的，而不是任何主題都能套的模板。

## 六、輸出規則

- 使用者只要成品：只給最終內容，不顯示分析、檢查過程與修改理由。
- 使用者要診斷：分四塊給（意圖推測、診斷、修改原則、最終版本）。
- 預設只給一個最佳版本；多版本要使用者明說，避免用相似選項增加決策負擔。
